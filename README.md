## 1. 처음 한 번만 하는 설정

### 1-1. Git 설치 확인

터미널(Mac은 터미널, Windows는 Git Bash 또는 명령 프롬프트)에 아래를 입력합니다.

```bash
git --version
```

버전이 뜨면 설치돼 있는 겁니다. 안 뜨면 [git-scm.com](https://git-scm.com/)에서 설치하세요.

### 1-2. 내 이름과 이메일 등록 (최초 1회)

깃허브에 뭘 저장할 때마다 "누가 했는지" 기록되는데, 이걸 미리 설정해둬야 합니다.

```bash
git config --global user.name "본인 이름 또는 깃허브 아이디"
git config --global user.email "본인 깃허브 가입 이메일"
```

### 1-3. 저장소 내려받기 (clone)

프로젝트를 처음 시작할 때 딱 한 번만 합니다. 원하는 폴더로 이동한 뒤:

```bash
git clone https://github.com/khuda-data/10th-toy-team5.git
cd 10th-toy-team5
```

이러면 우리 팀 저장소 전체가 내 컴퓨터에 복사됩니다. **팀원 전원이 각자 자기 컴퓨터에 이 과정을 한 번씩 해야 합니다.**

## 2. 매번 작업 시작 전에 하는 것

**작업을 시작하기 전엔 항상 최신 상태로 맞추고 시작하세요.** 다른 팀원이 먼저 올린 내용이 있을 수 있습니다.

```bash
git pull
```

이걸 안 하고 작업하면, 나중에 push할 때 다른 사람 내용과 충돌(conflict)이 날 수 있습니다. **작업 시작 전 `git pull`은 습관처럼 매번 하세요.**

## 3. 작업하고 저장하는 방법 (commit)

Git은 "저장"을 두 단계로 나눠서 합니다. 처음엔 헷갈릴 수 있는데, 순서만 외우면 됩니다.

### 3-1. 지금 상태 확인

파일을 수정한 뒤, 뭐가 바뀌었는지 먼저 확인하는 습관을 들이세요.

```bash
git status
```

빨간색으로 바뀐 파일 목록이 뜹니다.

### 3-2. 저장할 파일 담기 (add)

```bash
git add 파일이름.ipynb
```

여러 개를 한 번에 담으려면:

```bash
git add .
```
(`.`은 "바뀐 파일 전부"라는 뜻입니다)

### 3-3. 실제로 기록하기 (commit)

```bash
git commit -m "여기에 메시지 작성"
```

**이 메시지를 어떻게 쓸지는 아래 4번 항목이 우리 팀 규칙입니다. 꼭 읽어주세요.**

## 4. 커밋 메시지 작성 규칙 (필수)

우리 팀은 커밋 메시지에 **①무엇을 했는지 간단한 설명, ②어떤 파일을 수정했는지, ③작업 일자**를 반드시 포함합니다. 나중에 누가 뭘 언제 바꿨는지 커밋 목록만 보고 바로 알 수 있게 하기 위해서입니다.

### 형식

```
[설명] 한 줄 요약

- 수정 파일: 파일명1, 파일명2
- 작업 일자: YYYY-MM-DD
```

### 실제 예시

```bash
git commit -m "[설명] 무슨 파일 190줄 ~ 250줄 상세페이지 파싱 함수에 조회수·스크랩수 선택자 추가

- 수정 파일: linkareer_crawler.ipynb
- 작업 일자: 2026-08-08"
```

터미널에서 여러 줄짜리 메시지를 쓸 땐 `-m`을 여러 번 쓰는 방법도 있습니다.

```bash
git commit -m "[설명] 무슨 파일 190줄 ~ 250줄 상세페이지 파싱 함수에 조회수·스크랩수 선택자 추가" -m "- 수정 파일: linkareer_crawler.ipynb" -m "- 작업 일자: 2026-08-08"
```

### 간단 버전 (한 줄로 끝내고 싶을 때)

작은 수정이라 굳이 길게 안 써도 될 땐 이 형식으로 한 줄에 압축해도 됩니다.

```bash
git commit -m "[설명] recruit_count 결측 처리 로직 수정 | 파일: preprocessing.ipynb | 2026-08-08"
```

**중요**: `"수정함"`, `"업데이트"`, `"fix"` 처럼 뭘 했는지 알 수 없는 메시지는 지양해주세요. 나중에 팀원이 커밋 목록만 보고 어떤 작업을 언제 했는지 파악할 수 있어야 합니다. 따라서 설명 메시지를 무슨 파일 어디 부분을 작업했는지에 대해서도 적어주시는 것을 지향해주세요.

## 5. 내 컴퓨터 → 깃허브로 올리기 (push)

commit까지는 **내 컴퓨터 안에만** 저장된 상태입니다. 팀원들이 볼 수 있게 하려면 push까지 해야 합니다.

```bash
git push
```

이제 깃허브 저장소(https://github.com/khuda-data/10th-toy-team5)에 들어가서 새로고침해보면 방금 커밋한 내용과 메시지가 보입니다.

### 전체 순서 요약

```bash
git pull                          # 1. 최신 상태로 맞추기
# (여기서 파일 작업/수정)
git add .                         # 2. 바뀐 파일 담기
git commit -m "[설명] ... | 파일: ... | 날짜: ..."   # 3. 기록하기
git pull                          # 4. 최신 상태로 맞추기
git push                          # 5. 깃허브에 올리기
```

이 5줄이 매번 반복하는 기본 루틴입니다.

**중요** 이 작업까지 완료하고 깃허브에 파일이 올려진 것을 확인했으면 카톡방에 업데이트 했다는 것을 알려주세용!

## 6. 자주 겪는 문제 해결

### "Updates were rejected" 라는 에러가 뜰 때

다른 팀원이 나보다 먼저 push해서 생기는 문제입니다. 아래 순서로 해결하세요.

```bash
git pull
```

이때 같은 파일을 서로 다르게 고쳤으면 "충돌(conflict)"이 날 수 있습니다. 파일을 열어보면 이런 표시가 생깁니다.

```
<<<<<<< HEAD
내가 수정한 내용
=======
다른 팀원이 수정한 내용
>>>>>>> (커밋 정보)
```

두 내용 중 남길 걸 고르거나 합쳐서 정리한 뒤, 저 기호들(`<<<<<<<`, `=======`, `>>>>>>>`)을 지우고 다시 저장합니다. 그리고:

```bash
git add .
git commit -m "[설명] 충돌 해결 | 파일: ... | 날짜: ..."
git push
```


### 실수로 커밋 메시지를 잘못 썼을 때

아직 push 전이면:

```bash
git commit --amend -m "새로 쓸 메시지"
```

이미 push했으면 그냥 넘어가도 괜찮습니다. 억지로 되돌리려다 더 꼬이는 경우가 많습니다.

### 뭘 바꿨는지 모르겠고 그냥 원래대로 되돌리고 싶을 때

아직 commit 전이라면:

```bash
git checkout -- 파일이름
```

이러면 마지막 커밋 상태로 그 파일이 되돌아갑니다. (저장 안 한 수정사항은 사라지니 주의)

## 7. 용어 정리

| 용어 | 뜻 |
|---|---|
| Repository (저장소) | 우리 프로젝트 전체가 들어있는 공간. 지금 이 `10th-toy-team5`가 저장소입니다 |
| Clone | 깃허브에 있는 저장소를 내 컴퓨터로 통째로 복사해오는 것 (최초 1회) |
| Commit | 지금까지 바뀐 내용을 하나의 "저장 지점"으로 기록하는 것 |
| Push | 내 컴퓨터의 commit 내용을 깃허브(온라인)로 올리는 것 |
| Pull | 깃허브에 있는 최신 내용을 내 컴퓨터로 받아오는 것 |
| Branch | 같은 저장소 안에서 독립적으로 작업할 수 있는 또 다른 작업 공간 (이번 프로젝트는 우선 하나의 main 브랜치로 진행) |
| Conflict (충돌) | 같은 파일의 같은 부분을 여러 명이 다르게 고쳐서 자동으로 합쳐지지 않는 상황 |
